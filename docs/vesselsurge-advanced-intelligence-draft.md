# VesselSurge Advanced Intelligence Draft

Status: Draft for review before implementation and deploy
Target: Turn VesselSurge from a live maritime map into an operational intelligence platform for shipping operators, insurers, analysts, cargo teams and vessel owners.

## Product Goal

VesselSurge should answer three questions fast:

1. What is happening now?
2. What is likely to happen next?
3. What should an operator, insurer, analyst or cargo desk do about it?

Every feature below must be source-backed, freshness-gated and clearly labelled as signal, forecast, recommendation or user-configured workspace. No unverified breaking claims should be shown as fact.

## Proposed Navigation

Keep the product structured instead of adding everything onto the live map.

- Live Map: current vessel context, hotspots, reviewed news, anomaly flags.
- Alerts: AI alerts, predictive risk, notification settings.
- Intelligence Brief: automatic news summaries and operational recommendations.
- Playback: timeline, event replay and historical signal context.
- Ports: congestion and delay predictions.
- Market Pro: market impact, insurance pressure, commodity/freight signals.
- Network: AI cargo-vessel matching, counterparty verification, templates.
- Workspaces: custom dashboards such as Tanker Operations or Insurance Desk.

## 1. AI Alerts And Predictive Risk Models

User value: show what may happen next, not just what happened.

Example customer-facing output:

> Bab el-Mandeb risk is rising. VesselSurge estimates a 40% higher disruption probability over the next 48h based on new security reports, AIS behavior and rerouting language.

Implementation:

- Add a `predictive_risk_scores` model/table with region, horizon, score, delta, confidence, drivers and generated_at.
- Generate risk forecasts from:
  - reviewed live-map news
  - maritime_signals
  - source quality
  - freshness
  - AIS anomaly count
  - route-specific keywords such as attack, warning, rerouting, insurance, convoy, delay
- Show only forecasts that pass a minimum confidence gate.
- Use simple labels: Low, Watch, Rising, High.

First version:

- Region-level 24h and 48h risk only.
- No vessel-specific predictions until AIS quality is stronger.
- Store exact drivers so every forecast can explain why.

Acceptance checks:

- Forecast includes source count, latest source timestamp and confidence.
- No forecast older than 2h appears as live.
- Forecast endpoint returns fallback cached data if upstream fetch fails.

## 2. Automated News Summaries And Recommendations

User value: reduce noise and turn news into actions.

Recommendation categories:

- Routing: continue, monitor, reroute watch, avoid route.
- War risk insurance: normal, review premium, require broker check.
- Speed adjustment: normal speed, reduce exposure time, slow-steam watch.
- Cargo/vessel planning: delay risk, alternative route, document risk.

Implementation:

- Add `intelligence_briefs` generated from fresh reviewed articles and signals.
- Each brief should have:
  - headline
  - plain-English summary
  - affected route
  - recommended action
  - evidence list
  - confidence
  - valid_until
- Display in an Intelligence Brief panel, not mixed into every map card.

First version:

- One route brief per hotspot.
- Generated by cron after maritime update.
- Keep text under 90 words per route.

Acceptance checks:

- Brief uses only articles/signals under freshness thresholds.
- Every recommendation links to evidence.
- UI shows published time and valid_until.

## 3. Anomaly Detection And Critical Push Alerts

User value: flag suspicious behavior before it becomes a headline.

Anomalies:

- Loitering: vessel stays unusually long in a watch box.
- AIS gaps: vessel disappears near a critical route.
- Dark activity: AIS gap plus route risk context plus source signal.
- Route deviation: vessel moves away from expected transit path.
- Cluster pressure: many vessels slowing or bunching in a short window.

Implementation:

- Add `vessel_anomalies` with vessel_id/mmsi, region, anomaly_type, severity, confidence, evidence and detected_at.
- Start with deterministic rules before ML:
  - speed under threshold for too long
  - stale AIS position near hotspot
  - repeated heading changes near chokepoint
  - missing update beyond expected interval
- AI can summarize anomaly meaning, but rule output should remain visible.

Push notifications:

- Add notification preferences for logged-in users:
  - route
  - severity threshold
  - alert type
  - email/push toggle
- First version should use email or in-app notifications. Browser push can follow after permissions and unsubscribe flows are robust.

Acceptance checks:

- Critical alert must include anomaly type, time, region, evidence and confidence.
- No duplicate notifications for same anomaly within a cooldown window.
- User can disable alerts.

## 4. Custom Dashboards And Workspaces

User value: different users need different views.

Workspace presets:

- Tanker Operations:
  - Hormuz, Suez, Bab el-Mandeb
  - tanker/oil/LNG keywords
  - AIS anomaly panel
  - routing and delay recommendations
- Insurance Desk:
  - war-risk language
  - incident history
  - confidence and source quality
  - premium pressure estimate
- Freight Desk:
  - port congestion
  - delay predictions
  - rerouting and freight-rate signals
- Cargo Matching:
  - available capacity
  - route requests
  - match score

Implementation:

- Add `user_workspaces` with owner_id, name, preset, filters, layout and created_at.
- Start with server-rendered presets, then allow edits.
- Keep widgets modular: Map, Alerts, Brief, News, Ports, Market, Network.

Acceptance checks:

- Logged-in user can create, rename and load a workspace.
- Workspace filters persist.
- Default workspace still works for users without custom setup.

## 5. Better Search And Filters

User value: quickly find a vessel, route or event type.

Search types:

- Vessel name or MMSI
- Region or route
- Event type: attack, warning, rerouting, congestion, AIS gap, insurance, tanker, oil
- Source
- Time window

Implementation:

- Replace generic search results with typed results:
  - Vessel
  - News
  - Signal
  - Anomaly
  - Route
  - Port
- Add quick filters to live map and latest pages:
  - last 6h, 24h, 72h
  - reviewed only
  - critical/high only
  - tanker/container/LNG
- Add query params so searches are shareable.

Acceptance checks:

- Search returns in under 500ms for cached/common searches.
- Empty state suggests route pages and live map.
- Results show source time and confidence.

## 6. History And Playback

User value: understand how an incident developed.

Features:

- Timeline per hotspot.
- Playback slider for signals/news/anomalies.
- Event chain view: first source, confirmation, operational impact, current status.

Implementation:

- Add a `/playback` or embedded route timeline.
- Store snapshots of risk score, article count, signal count and anomaly count.
- Use existing cache/update runs as historical checkpoints.

First version:

- 7-day event timeline for each core hotspot.
- No heavy map animation yet; start with timeline cards and risk chart.

Acceptance checks:

- Timeline never labels old data as live.
- Current state is visually separated from historical state.
- Users can filter by route and event type.

## 7. Port Congestion And Delay Predictions

User value: know where delays may form and how severe they are.

Signals:

- Queue size
- AIS density
- vessel speed near port approaches
- weather constraints
- news mentions
- canal/port advisories

Implementation:

- Add `port_delay_scores` for port/region, delay_minutes_estimate, confidence, source_count, drivers and generated_at.
- Start with ports linked to chokepoints:
  - Singapore
  - Port Said/Suez
  - Jeddah/Red Sea
  - Fujairah/Gulf
  - Rotterdam as market reference
- Add a Ports panel with simple labels:
  - Normal
  - Building delay
  - Congested
  - Severe

Acceptance checks:

- Delay prediction has generated_at and expires quickly.
- If AIS is unavailable, show “source-only estimate”.
- Do not invent exact queue numbers without a source.

## 8. Environmental And ESG Data

User value: prepare for charterer, insurer and regulatory questions.

Signals:

- Estimated emissions impact from rerouting.
- CII/EEXI context where public vessel data allows.
- Fuel-burn estimate from route extension.
- ESG alert when route change likely increases emissions.

Implementation:

- Start with route-level estimates, not vessel-certified ratings.
- Add simple formulas:
  - extra nautical miles
  - estimated fuel burn band
  - estimated CO2 band
- Label as “estimated” unless verified with source data.

Acceptance checks:

- ESG numbers show methodology.
- No vessel-specific CII claim unless the data source supports it.
- Exportable summary for customers.

## 9. War Risk And Insurance Integration

User value: translate maritime risk into insurance action.

Features:

- War-risk pressure indicator by region.
- Premium pressure estimate: normal, review, elevated, urgent.
- Broker-check recommendation when evidence is high.

Implementation:

- Source signals:
  - war-risk language in trusted sources
  - official advisories
  - incident/anomaly density
  - route risk forecast
- Add `insurance_pressure` output to Intelligence Brief and Market Pro.

First version:

- No exact premium numbers unless a source is available.
- Use pressure bands and recommendations.

Acceptance checks:

- Every insurance recommendation cites evidence.
- “Premium level” is not shown as a real price unless sourced.
- User can see what changed since last update.

## 10. B2B Network AI Matching

User value: make the network useful, not just a form.

Features:

- Match score between cargo request and vessel capacity.
- AI explanation: why this vessel/cargo fits.
- Counterparty verification checklist.
- Contract template library.

Implementation:

- Add normalized fields:
  - cargo type
  - route
  - laycan/date window
  - volume
  - vessel type
  - constraints
  - contact verification status
- Add `network_matches` with request_id, offer_id, score, explanation and status.
- Use AI to draft intro messages and contract checklist.

First version:

- Internal/admin match suggestions.
- Then customer-visible “recommended matches” after moderation.

Acceptance checks:

- No contact details exposed without permission.
- Match score includes explainable fields.
- Templates are clearly labelled as drafts, not legal advice.

## Data Trust Rules

All intelligence features must follow these rules:

- Freshness gate:
  - live-map news: under 96h
  - Market Pro news: under 72h
  - Market Pro signals: under 48h
  - predictive risk: generated under 2h
- Source gate:
  - official, tier-1, trade or reviewed search-surfaced source
  - weak sources can support watch status but not high-confidence claims
- Explainability:
  - every alert, forecast or recommendation must show drivers
  - every driver links back to source, signal or AIS rule
- Safety:
  - no “guaranteed” predictions
  - no precise insurance premiums without source
  - no personalized financial advice

Phase 3: Workspaces And Port Delays

1. Add workspace presets.
2. Add port delay scores.

Phase 4: Insurance, ESG And B2B AI

1. Add insurance pressure bands.
2. Add ESG route estimates.

## Recommended First Deploy Slice

The safest first deploy should include:

- Alerts page shell.
- Predictive risk API with 24h/48h route scores.
- Intelligence brief cards for each hotspot.
- Freshness/source gates shared with live map.
- SEO metadata for “shipping disruption alerts”, “predictive maritime risk”, “war risk insurance shipping” and “port delay prediction”.

This first slice gives visitors a clear new reason to return without overloading live map or inventing unsupported data.
